# 图像去模糊 / 超分能力：技术调研与选型报告

> 面向 Python 智能体、**纯 CPU 部署**、以**截图/文档/UI** 为主的图像清晰化能力调研。
> 调研数据核实日期：**2026-11-18**（GitHub REST API + LICENSE 原文）。

---

## TL;DR

**先上方案一，用埋点数据决定要不要方案二。**

| | 方案一（推荐先做） | 方案二（按需追加） |
|---|---|---|
| 一句话 | 小模型 + 强编排，同步秒级返回 | 大模型 + 文本分治，异步分钟级 |
| 核心模型 | Real-ESRGAN `general-x4v3`（1.2M）+ NAFNet-width32 | Real-ESRGAN `x4plus`（16.7M）+ NAFNet-width64 + SwinIR |
| 时延 | **实测**：400×300 ≈ 1.7~2.1s；720p ≈ 14.5s；1080p ≈ 33s | 25~80s，异步队列 |
| 画质 | 中等，保真不幻觉 | 较高，框内保真/框外强 |
| 许可证 | BSD-3 / MIT / Apache-2.0，全部可商用 | 同左 |
| 落地成本 | 3~5 人日 | 2~3 周 |

**三条不可妥协的红线：**

1. **文字场景禁用生成式先验** —— GAN 会把 `rn` 重绘成 `m`，这是内容错误，不是画质问题。
2. **不用扩散模型** —— SUPIR/StableSR/CodeFormer 非商用；DiffBIR 在文字上会幻觉笔画；CPU 上单图分钟级。
3. **永不抛异常** —— 模型缺失/超时/算子不支持一律降级到 Lanczos，Agent 会话不能因为一张图挂掉。

## 决策速查表

| 你的情况 | 档位 | 模型链路 | 预期 |
|---|---|---|---|
| 对话中用户发来模糊截图，等结果 | 交互档 | x4v3（≤0.15MP）／大图自动降级快链路 | 小图 1.7~2.1s；大图走 FSRCNN/Lanczos 并在 3s 内返回 |
| 批量清洗知识库截图（几千张） | 离线档 | x4plus + 文本分治（+ SwinIR 可选） | 1~2.5 张/分钟/8 核 |
| 手机翻拍文档，有运动/失焦模糊 | 交互档先试 | NAFNet + x4v3 | 有改善则停；不满意转离线 |
| 老照片"修复"（期望补细节） | **不支持** | — | 需扩散模型 + GPU + 商业授权，另立项 |
| 图片本来就很清晰 | `none` | 直接返回 | < 30ms，`warnings=[already_sharp]` |

## 核心术语

| 术语 | 含义 |
|---|---|
| **退化类型** | `lowres`（低分辨率）/ `jpeg`（压缩伪影）/ `motion`（运动模糊）/ `defocus`（失焦模糊）/ `mixed`（混合） |
| **内容类型** | `text_ui`（纯文字 UI，保真优先）/ `mixed`（图文混排，分治）/ `photo`（纯图像，可强） |
| **保真链路** | 禁用 GAN 生成式先验、限制锐化增益的处理路径 |
| **生成式先验** | GAN/扩散模型带来的"补细节"能力，同时也带来"编细节"风险 |
| **分块（tiling）** | 大图切成小块分别推理再融合，控制峰值内存；关键是在**放大后空间**融合 |
| **兜底（fallback）** | 模型不可用时回落到 Lanczos 插值 + 弱锐化，保证始终有输出 |
| **幻觉** | 模型生成了原图中不存在的笔画/文字，属内容错误 |

## 快速验证

```bash
cd poc
pip install -r requirements.txt
# 把 ONNX 权重放到 poc/models/（见 poc/models/README.md）
python deblur_tool.py --input samples/blurry.png --scale 2 --out out/sharp.png
```

无权重也能跑：会自动回落到 OpenCV FSRCNN → Lanczos，用于验证链路与耗时基线。
